# دليل اسئلة المقابلات الفنية الشامل لمهندسي الذكاء الاصطناعي (LangChain Modern Updates)

يغطي هذا الدليل اهم الاسئلة الفنية المتوقعة في مقابلات التوظيف لوظائف:
- **AI / LLM Engineer**
- **Generative AI Developer**
- **Agentic AI Solutions Architect**

تم تصنيف الاسئلة حسب المحاور والمستويات التقنية من المبتدئ الى المتقدم.

---

## المحور الاول: التحديثات الهيكلية والمعمارية العامة

### س1: ما الفروق الجوهرية بين اصدارات LangChain القديمة (v0.1 / v0.2) والاصدارات الحديثة (v0.3 / v1.x)؟
**الاجابة النموذجية**:
1. **تفكيك الحزم (Modular Architecture)**: تم فصل المكتبة الضخمة الواحدة الى حزم رشيقة ومستقلة:
   - `langchain-core`: الواجهات الاساسية و Runnables والرسائل والادوات بدون اي تبعيات ثقيلة.
   - `langchain-community`: الادوات والموصلات الخارجية التابعة للمجتمع.
   - الحزم المتخصصة للمزودين مثل `langchain-openai`, `langchain-groq`, `langchain-anthropic`.
2. **محرك الوكلاء (Agent Runtime)**: التخلي التام عن `AgentExecutor` واعتماد `LangGraph` و `create_agent` لادارة الوكلاء كرسوم بيانية للحالات (State Graphs).
3. **التوحيد البرمجي**: اطلاق `init_chat_model` لتوحيد تهيئة النماذج، و `with_structured_output` لتوحيد استخراج البيانات المهيكلة.

### س2: ما هو مفهوم LCEL (LangChain Expression Language) ولماذا تم ابتكاره؟
**الاجابة النموذجية**:
هو نمط برمجي تعبيري يتيح تركيب سلاسل المعالجة وتدفقات العمل باستخدام عامل الانبوب (`|`).
تم ابتكاره لتوفير ميزات انتاجية قياسية جاهزة لكل مكون:
- دعم التدفق المباشر (Streaming support).
- دعم التنفيذ غير المتزامن (Async support).
- امكانية التوازي التلقائي للمكونات المستقلة.
- امكانية التراجع والتتبع التلقائي في ادوات المراقبة مثل LangSmith.

## المحور الثاني: تكامل النماذج واستدعاء الوكلاء

### س3: متى نستخدم init_chat_model وكيف تساهم في تطبيق افضل الممارسات الهندسية؟
**الاجابة النموذجية**:
تُستخدم لإنشاء تطبيقات غير مقيدة بمزود وحيد (Vendor-agnostic). تساهم هندسيا في:
- فصل التكوين عن منطق العمل (Separation of Concerns).
- امكانية تبديل النماذج في بيئات الاختبار والتشغيل عبر متغيرات البيئة بدون تعديل في الكود.
- توحيد قراءة البيانات الاحصائية لاستهلاك الرموز عبر `usage_metadata`.

### س4: ما الفرق بين invoke و ainvoke و stream و batch؟ ومتى تختار كل نمط؟
**الاجابة النموذجية**:
- `invoke`: متزامن لطلب مفرد؛ مناسب للاختبار والمهام غير التفاعلية.
- `ainvoke`: غير متزامن؛ اساسي في تطبيقات الويب الحديثة (FastAPI / Asyncio) لمنع حظر خيط التنفيذ الرئيسي (Event Loop).
- `stream`: تدفقي؛ حاسم لتطبيقات المحادثة التفاعلية لتقليل وقت انتظار الرمز الاول.
- `batch`: معالجة متوازية لمجموعة من الطلبات؛ مثالي لمهام استخراج وتحليل البيانات مع امكانية تحديد `max_concurrency` لتفادي Rate Limits.

## المحور الثالث: استدعاء الادوات وبروتوكول Tool Calling

### س5: اشرح بالتفصيل دورة حياة استدعاء الادوات (Tool Calling Lifecycle) في نماذج اللغة الحديثة.
**الاجابة النموذجية**:
1. يقوم المطور بتعريف الاداة وتحديد مخططها عبر `@tool`.
2. يتم تحويل مواصفات الاداة الى JSON Schema وارسالها ضمن طلب النموذج (`model.bind_tools`).
3. يحلل النموذج استفسار المستخدم ويقرر الحاجة للاداة، فيعيد ردًا بنوع `AIMessage` يحتوي على حقل `tool_calls` يتضمن اسم الاداة ووسائطها ومعرفا فريدا `tool_call_id`.
4. يقوم النظام بتنفيذ دالة الاداة باستخدام تلك الوسائط.
5. تعاد النتيجة في رسالة `ToolMessage` تحمل نفس `tool_call_id`.
6. يرسل السجل كاملا للنموذج مرة اخرى لإنتاج الرد النهائي للمستخدم.

### س6: كيف تضمن ان النموذج اللغوي يمرر المعاملات الصحيحة للاداة دون اخطاء برمجية؟
**الاجابة النموذجية**:
1. استخدام Pydantic schema محكمة مع وضع قيود (`ge`, `le`, regex).
2. كتابة اوصاف واضحة ومفصلة في `Field(description=...)`.
3. كتابة Docstring شامل للدالة يوضح سياق الاستخدام.
4. تفعيل وضع التحقق الصارم (Strict Mode) اذا كان المزود يدعمه (مثل OpenAI Structured Outputs).
5. تزويد الاداة بآلية معالجة استثناءات تعيد رسالة خطأ مفهومة للنموذج لتمكينه من تصحيح نفسه.

## المحور الرابع: الإخراج المهيكل (Structured Outputs)

### س7: ما هو الفرق بين model.with_structured_output واستخدام استدعاء الدوال اليدوي؟
**الاجابة النموذجية**:
دالة `with_structured_output` هي غلاف عالي المستوى (High-level wrapper):
- تتولى تحويل كلاسات Pydantic او TypedDict او Dataclass الى المخطط المطلوب تلقائيا.
- تجبر النموذج على الالتزام بالمخطط عبر تقنيات المزود الاصلية.
- تقوم بفحص ومطابقة النتيجة المرتجعة تلقائيا واعادتها ككائن جاهز للاستخدام بدلا من اعادة نصوص JSON تتطلب معالجة يدوية.

### س8: قارن تقنيا بين استخدام Pydantic مقابل TypedDict مقابل Dataclass لاستخراج البيانات.
**الاجابة النموذجية**:
- **Pydantic**: الخيار الامثل للانتاج؛ يدعم فحص القيود الصارمة اثناء التشغيل، والتحقق التلقائي من البريد والارقام والشروط المركبة.
- **TypedDict**: خفيف جدا؛ بدون اي تبعيات خارجية، يعيد قواميس بايثون نقية، مناسب للبيانات البسيطة ولتوفير اقصى سرعة.
- **Dataclass**: جزء من مكتبة بايثون القياسية؛ يتيح استخدام خصائص الكائنات (`obj.field`) بدون تبعيات خارجية، مناسب للتوافق مع الشيفرات القديمة.

## المحور الخامس: إدارة سياق المحادثة والذاكرة (Context & Memory)

### س9: ما هي التحديات التقنية التي تواجه ذاكرة الوكلاء في المحادثات الطويلة وكيف تحلها؟
**الاجابة النموذجية**:
التحديات:
1. استهلاك وتجاوز حد نافذة السياق (Context Window Overflow).
2. الارتفاع الحاد في تكاليف التوكنات وزمن الاستجابة.
3. التشتت المعرفي للنموذج (Lost in the middle phenomenon).

الحلول الحديثة:
- استخدام `trim_messages` لتقليم الرسائل بناء على عدد التوكنات مع الحفاظ على رسائل النظام وسلامة ازواج الادوات.
- تطبيق `SummarizationMiddleware` لتلخيص الرسائل القديمة تلقائيا عند بلوغ حد معين واستبدالها بسياق مكثف.
- تخزين المحادثات المفهرسة في قواعد بيانات متجهة (Vector Stores) لاسترجاع الرسائل الاكثر صلة دلاليا فقط.

## المحور السادس: البرمجيات الوسيطة والحوكمة (Middleware & HITL)

### س10: ما هي البرمجيات الوسيطة (Agent Middleware) في LangChain 1.x وما ابرز انواعها؟
**الاجابة النموذجية**:
هي طبقة برمجية تعترض طلبات واستجابات الوكيل الذكي قبل او بعد استدعاء النموذج او الادوات لتطبيق سياسات محددة.
ابرز انواعها المدمجة في `langchain.agents.middleware`:
- `SummarizationMiddleware`: لادارة وضغط سياق المحادثة.
- `HumanInTheLoopMiddleware`: لحظر وتنظيم تنفيذ العمليات الحساسة بانتظار موافقة بشرية.
- `PIIMiddleware`: لاكتشاف وحجب البيانات الشخصية الحساسة (Personally Identifiable Information).
- `ToolErrorMiddleware` و `ToolRetryMiddleware`: لمعالجة اعادة محاولة تنفيذ الادوات عند الفشل.

### س11: كيف تصمم معمارية وكيل ذكي آمن للعمليات البنكية مع تطبيق Human-in-the-Loop؟
**الاجابة النموذجية**:
1. تصنيف الادوات الى:
   - ادوات قراءة واستعلام (Read-only / Safe): مثل كشف الحساب؛ تعمل بتفويض كامل.
   - ادوات كتابة وتنفيذ (Write / Critical): مثل تحويل الاموال وسداد الفواتير.
2. تكوين `HumanInTheLoopMiddleware` مع تفعيل `interrupt_on` للادوات الحرجة.
3. ربط الوكيل بمخزن حالات دائم (State Checkpointer مثل PostgresSaver).
4. عند طلب تحويل، يوقف محرك الرسم البياني التنفيذ ويحفظ الحالة مع معرف `thread_id`.
5. يتم ارسال اشعار عبر واجهة الاشراف (UI) يوضح تفاصيل العملية.
6. عند اعتماد المشرف، يتم استدعاء امر استئناف الجلسة مع خيار الموافقة او التعديل.

## المحور السابع: تحديات وسيناريوهات برمجية (Coding Challenges)

### تحدي 1: اكتب دالة تنشئ وكيلا يتعامل مع اداة حسابية باستخدام احدث صيغ LangChain.
```python
from langchain.chat_models import init_chat_model
from langchain.agents import create_agent
from langchain_core.tools import tool

@tool
def multiply(a: float, b: float) -> float:
    """Multiply two numbers together accurately."""
    return a * b

def build_math_agent():
    model = init_chat_model("openai/gpt-oss-120b", model_provider="groq", temperature=0)
    agent = create_agent(
        model=model,
        tools=[multiply],
        system_prompt="You are a math assistant. Always use tools for calculations."
    )
    return agent
```

### تحدي 2: كيف تضمن تقليم محادثة بحيث لا تتجاوز 2000 توكن مع ضمان بقاء رسالة النظام في البداية؟
```python
from langchain_core.messages import trim_messages

def get_safe_context(messages, model):
    return trim_messages(
        messages,
        max_tokens=2000,
        strategy="last",
        token_counter=model,
        include_system=True,
        start_on="human"
    )
```
